BeitDesk — Administrator Guide

Complete reference for managing BeitDesk

🚀 Starting the System

Normal HTTP (development / LAN without PWA)

py manage.py runserver 0.0.0.0:8000

HTTPS (required for PWA install + camera MFA on other devices)

python run_https.py
HTTPS certificates: run mkcert -install && mkcert 192.168.1.171 localhost 127.0.0.1 once to create cert files. Update IP in run_https.py and settings.py to match your machine's LAN IP (ipconfig).

First-time setup

pip install -r requirements.txt py manage.py migrate py manage.py seed_data py manage.py createsuperuser

The seed data does not create any user accounts. Create your administrator with the command above, then add everyone else from Users → Create User.

👥 User Management

Permission Levels

  • Administrator (superuser) — full access to all features, can promote users, manage T&C, delete backups, restore databases
  • IT Staff (is_staff) — manage all tickets, assets, KB articles, create backups, view all users
  • Regular User — can only see their own tickets and KB articles

Creating Groups (recommended)

Go to Admin → Authentication → Groups. Create:

  • IT Staff — assign all staff. Gives is_staff=True
  • IT Admin — assign senior staff. Gives is_superuser=True

Promote a user to admin

Admin Panel → Users → select user → tick "Superuser status" → Save

🔒 MFA — Face Recognition & TOTP

How MFA works

  1. User logs in with username + password
  2. If MFA is enabled on their account → redirected to verification page
  3. Face tab: camera opens, blink detected for liveness, face compared to stored embedding
  4. If face matches (≥75% confidence) → logged in. If not → try TOTP or backup code

Enrolling a user's face

Visit /accounts/mfa/enroll/?user_id=<pk> as admin, or ask user to visit /accounts/mfa/enroll/ themselves.

Face recognition requires HTTPS and a camera. On HTTP (localhost only), camera works. On LAN devices, start the HTTPS server first.

Unlocking a locked face account

After 5 failed face attempts, account locks for 15 minutes. Admin can unlock at: /accounts/mfa/settings/ → scroll to unlock section.

TOTP Setup (Google Authenticator)

  1. User visits MFA Settings → scans QR code with Google Authenticator or Authy
  2. Enters 6-digit code to confirm → TOTP activated
  3. 8 backup codes generated — user should save these
If a user loses their authenticator and has no backup codes, reset their TOTP secret from Admin Panel → UserProfiles → clear totp_secret and set totp_enabled=False

📋 Terms & Conditions

  • Current T&C version is shown at /accounts/terms/
  • Manage versions at /accounts/terms/admin/ (superusers only)
  • Publishing a new version resets all users' acceptance — everyone re-accepts on next login
  • Every acceptance is logged with timestamp and IP in UserTermsAcceptance

🗄 Database Backup & Restore

Create a backup

Dashboard → DB Backup → Create New Backup. Saves to backups/ folder.

For SQLite (dev): copies .db file. For PostgreSQL (prod): uses pg_dump — ensure it's on your PATH.

Restore (admin only)

Restore OVERWRITES the current database. Always create a new backup before restoring.

Year Databases

BeitDesk supports multiple year databases. Register years at Dashboard → Database / Year. Staff can switch to a past year at login to view historical records. Past-year databases are read-only in the UI.

📊 SLA Escalation (Scheduling)

Manual run

py manage.py check_sla py manage.py check_sla --dry-run # preview without sending

Schedule on Windows (every 30 minutes)

schtasks /create /tn "BeitDesk SLA" /tr "C:\path\to\.venv\Scripts\python.exe C:\path\to\manage.py check_sla" /sc minute /mo 30 /st 00:00

Schedule on Linux (cron)

*/30 * * * * cd /path/to/beitdesk && python manage.py check_sla >> /var/log/beitdesk_sla.log 2>&1

Escalation levels: 1=Warning (within 2h of due), 2=Breached (past due), 3=Critical (24h+ overdue).

📱 PWA Installation

  • Windows Chrome/Edge — install prompt appears automatically on HTTPS. Or click ⊕ in address bar
  • Android Chrome — install banner appears after 30 seconds on HTTPS site
  • iPhone (Safari) — Share button → Add to Home Screen (iOS cannot show auto-prompt)
  • Other LAN devices — open https://<your-ip>:8000 in Chrome, install from menu
Camera (face MFA) and PWA install both require HTTPS. Start python run_https.py for LAN devices.

📤 Data Export

  • Tickets CSV — Dashboard → Export CSV (IT Staff + Admin only)
  • Assets CSV — Assets → Export CSV (IT Staff + Admin only)
  • Both exports include all current filter selections

🔧 Troubleshooting

Camera won't start

  • Ensure you're on HTTPS (python run_https.py), not HTTP
  • Allow camera permissions in browser (click lock icon in address bar)
  • Use Chrome or Edge — Firefox and Safari have limited support
  • Check that a webcam is physically connected

QR code not showing

  • Ensure internet access (loads qrcode.js from CDN)
  • Try refreshing the page
  • Use the manual key entry instead — copy the secret into your authenticator app

Face not recognised

  • Improve lighting — face should be well-lit from the front
  • Re-enroll face in better lighting conditions
  • Use authenticator app as fallback
  • Admin can clear face lock: MFA Settings → scroll down

DB backup fails

  • SQLite: ensure nexusdesk.db is not locked by another process
  • PostgreSQL: ensure pg_dump is installed and on PATH
  • Check backups/ folder exists and is writable
